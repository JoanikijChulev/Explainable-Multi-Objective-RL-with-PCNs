Command-Space Counterfactual Explanations for Pareto-Conditioned Reinforcement Learning - Showcase

How this works — in one minute

🎯 The agent follows a goal. Its goal is a wish list: how much of each thing it should try to get (treasure, time, fuel, …). Give it a different wish list and it behaves differently — that's the whole trick.

🤔 When you ask "why not that move?", the method (called CF-ZOO) quietly asks the agent's brain tens of thousands of "what if" questions: "if your wish list were slightly different — would you do it then?" The world doesn't move at all during this; only the agent's brain is being questioned.

⚖️ It hunts for the smallest change of heart. Out of all the wish lists that would make the agent take your move, it finds the one closest to the current goal. That's the answer you see: "if it had cared a little less about D and a little more about A, it would have gone right."

🚫 Sometimes the answer is "never". If no wish list at all makes the agent pick your move, that's not a failure — it tells you the move isn't part of any good strategy the agent knows from that situation.

🎬 "Show me" makes it real. The found change of heart is deliberately tiny, so acting on it directly can leave the agent confused. The show-me step picks the nearest real goal that starts with your wished move, lets the agent perform it, and plays the alternative story to the end.

The verified-realization protocol, literally step by step

This is what the “Continue rollout” button executes. Measured over all 2,534 counterfactuals the ZOO search achieves in the paper suite: 95.8% of realized episodes land on the learned Pareto front and 98.5% terminate properly (the misses are structural: tiny fronts or foils that exile the agent from every front-reachable region).
  1. Where you are. You stopped at timestep t. The agent has already collected some reward vector collected, its current command is remaining = desired − collected, and the CF search just found a command R_cf that makes the policy pick your foil action instead of its greedy one. The problem: R_cf was chosen to be minimal, so it usually sits exactly on the decision boundary — issue it naively and after the flip the agent can dither there forever, collecting nothing (we filmed this happening).
  2. Build the menu of trustworthy commands. A verified row contains an achieved Pareto target F_j and its tested witness command W_j. Convert the witness to a residual from here: candidate_j = clip(W_j − collected, bounds). (For RH models the candidate also carries the row's horizon minus the steps already spent.)
  3. Sort the menu. Order candidates by scaled distance to the current remaining command — try the most similar behaviour first, so the accepted counterfactual stays as close as possible to what the user was already asking for.
  4. Audition candidates one by one. For each candidate: rewind the environment to timestep t (deterministic fixed-seed replay of the prefix — a save-state restore, nothing semantic), issue the candidate as the new command, and simulate the whole future:
    1. First-action check: the very first action must equal the foil. If the policy still picks its old greedy action, REJECT after one step — this candidate does not realize the counterfactual at all.
    2. Landing check: roll greedily to the end; the achieved total (collected + suffix) must land within tolerance of some point in the verified front's landing archive. Reacher uses its curated 50-point verified front. If yes → ACCEPT, done.
  5. Fallback 1 — plain R_cf. If no front candidate passes both checks, issue the searched command R_cf itself and roll out. Sometimes the boundary command happens to behave fine.
  6. Fallback 2 — R_cf + snap-once. Issue R_cf so the foil definitely fires, take exactly one step, then re-anchor: replace the leftover command with the nearest front residual given what is now collected. The flip is real, and afterwards the agent follows a command it was actually trained on. (Known cost: if the nearest residual is the original plan, the agent may revert — the “revert tax”, ~5% of cases.)
  7. Exhaustion. If everything above fails, keep the best-effort rollout and say so explicitly. In the paper suite this only happens where it is provably impossible: fronts of size 1 (breakable-bottles, resource-gathering) or foils that exile the agent from every front-bearing subtree (three-tree, fruit-tree, branch-path timeout arithmetic).

Dummy example (Collect-Two, the paper's worked example)

  1. Command (0, 0, 0.8, 1) at t=0: greedy action is down (heading for D first). Foil: right. ZOO finds R_cf = (0, 0, 0.8, 0.844) — minimal, boundary-sitting.
  2. Naive R_cf realization: first action flips to right… then left, right, left for 50 steps. Timeout, nothing collected.
  3. Audition #1: nearest residual is (0, 0, 0.8, 1) — the original plan. First action comes out down ≠ foil → REJECT after 1 step.
  4. Audition #2: (0, 0, 1, 0.8). First action right ✓ — agent collects C (+1), then D (+0.8), terminates in 9 steps exactly on the front point (0, 0, 1, 0.8) → ACCEPT. Total cost: 2 auditions.
